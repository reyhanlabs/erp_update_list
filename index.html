Getting started

Login & account

Sign in with Google so the same plans and summaries appear on laptop and phone. Features that pull Redmine data or send Telegram require a Google account allowed by the app owner.

Continue as guest still works for plans and summaries, but data stays on that device and Redmine/Telegram menus stay inactive.

Moving from guest to Google? Sign in with Google on the same device. Guest data is moved into your Google account automatically when possible.

Team workspace

A workspace lets one team see the same plans and summaries in realtime. Everyone who joins with the same workspace code shares that data.

  1. One person opens Settings → Team Workspace, then clicks Copy code.
  2. Teammates paste the code in the workspace field and click Join.
  3. To return to personal data, click Use personal.
The workspace code works like a password. Share it only with teammates, and avoid short codes that are easy to guess.

Appearance & sidebar

Choose Light, Dark, or Auto (follow device settings) from the top-right buttons or Settings → Appearance.

The ☰ button left of the page title collapses the sidebar to an icon rail for a wider workspace. Hover an icon to see its label and count.

Install on phone

You can install this app like a normal app for quick access from your home screen.

  • Android (Chrome): open Settings → Install app, or menu ⋮ → Install app.
  • iPhone (Safari): Share → Add to Home Screen.

Update flow

Sync from Redmine

Pull issues from pjm.zahironline.com and save them as a new Update Plan, without copying URLs one by one.

  1. Open Update Plans, then click Sync Redmine.
  2. Choose Project, Status Filter (usually Resolved or Ready for Testing), and Date range.
  3. Click Preview to review issues. Ones already in a plan are marked Already added.
  4. Click Sync Now. New issues are saved as a plan with a Redmine tag.
Avoid the All date option unless you really need it — every issue in the project is pulled and it can be slow. If the connection is uncertain, click Test Connection first.

Update Plans

One plan holds the issue list for one release on one product line (Zahir ERP, Zahir ERP One, Manufacturing, or MRP).

  1. Click Add New Plan (or press N).
  2. Enter title, issue URLs (one per line), and notes if needed.
  3. Click Save Plan.

In the plan list, expand a card to see its issues. Use search (/), project filter, and the No summary / Has summary / Redmine chips to find plans quickly.

Update Summaries

A release summary ready to paste into a WA or Telegram group, built from an Update Plan.

  1. Click Add New Summary, then select its Update Plan.
  2. Enter FE / V2 / V3 versions and the release date.
  3. Choose template WA formal, WA singkat, or Telegram, then click Auto-generate. Issues are grouped by type using the Redmine tracker.
  4. Edit the result if needed, then click Save Summary.
Plans without a summary show up on the Needs Summary card on the Dashboard.

Daily features

Dashboard

The home page that summarizes everything: total plans, summaries, and issues; new issues per project; and Needs attention today — Immediate still New, On Progress stuck over 7 days, On Deploy, Rework, and Feedback.

Click any card to open the issue list behind it.

Tester Queue

Issues with status Ready for Testing from Zahir ERP, Zahir ERP One, and Manufacturing, split by category: Front End, Backend, Design, and Other. Category comes from the Redmine Category field.

  • Filter with search, project, and priority; group by project, assignee, or priority.
  • Copy list copies a paste-ready list for tester briefing.

Issue Status

The five menus under Issue Status show issues by work stage: New, On Progress, On Deploy, Resolved, Rework, and Feedback, combined across the Zahir projects. Sidebar numbers show the count per stage.

If Redmine status names differ, change them with the Status control in the toolbar. Copy all links copies every visible issue link.

Active Work

Shows In Progress and On Deploy issues, grouped by assignee by default, so each person’s load is easy to see.

What Next

Ranks New issues by what should be done first. Score uses priority (Immediate highest), wait time, and whether the issue is unassigned. Reasons appear on each row.

  • Copy top list copies the top list for discussion in meetings.
  • Create plan from top creates a new Update Plan from the top issues.

By Client

Lists every client from the Redmine field Client Name as a table with the same columns for everyone: New, In Progress, Ready for Testing, Resolved, Other open (feedback, rework, on deploy, …; hover for details), Open, Total and Last update, plus totals for the clients shown.

Only the three Zahir products are counted (ERP, ERP One, Zahir ERP Manufacturing); issues in other Redmine projects are left out. Filter by product, by name, or show only clients with open / New / In Progress / Ready for Testing / Resolved issues; click a column header to sort. Click a client (or press Enter) to see its issues grouped by status, with the product filter applied; ← All clients goes back. The list is built on the server and cached for an hour; Refresh reloads it.

Report tab (inside a client): every request grouped into Not started, In progress and Done (done items from the last 90 days; Show older for the rest). Each card shows what was asked (from the issue description; Actual/Expected for QA-format issues) and the latest progress note from Redmine, with who wrote it and when. Copy for WhatsApp / Telegram gives a ready-to-send summary; Export Excel (CSV) gives one row per issue.

Client Versions

A list you keep yourself: each client's name and the address of their Zahir ERP (for example apt.zahirerp.com, or the client's own domain such as erp.client.com; any public https address works). The version is read automatically from the client's public login page, the same number shown bottom-left before signing in, so you never type it.

  • Add client one by one, or Paste a list (name and address per line, straight from Excel).
  • Versions are checked when you add a client, when you open the menu (up to 100 sites whose last check is older than 6 hours), and with Check all versions.
  • Besides the front-end version, each check also reads the backend versions: API V2 from /api/v2/versions/dev and API V3 from /api/v3/version on the same address (no sign-in). The highest value of each column is green, older ones amber; click a client's name to see the raw answer.
  • Rollout cards on top show, for front-end, API V2 and API V3, the newest version and how many clients already run it (in %).
  • Recent changes lists every version change seen in the last 30 days (who, which part, from → to). Each client keeps its own version history (last 50 changes) in its details. Optionally, Settings → Telegram can post each batch of changes to your Telegram chat.
  • ⚠ Parts out of step marks a site whose front-end, API V2 and API V3 were built more than 14 days apart (read from the build stamp in the version, e.g. 2.26.10.081600 = 8 Oct 2026 16:00), which often means a deploy that was not finished.
  • Compare (top right, or Compare this site… in a client's details) puts 2–4 sites side by side, e.g. DEV, production and one client. The first column is the reference; every other column shows, per part, how many hours/days older or newer its build is, plus a one-line summary. Copy gives the comparison as text for chat; your choice of sites is remembered.
  • Tick Test / internal server in Edit for a dev or test site: it then doesn't set the Latest version, isn't counted in the rollout or Behind latest, and newer builds on it show in blue.
  • Filters on top: Latest FE, Latest V2 and Latest V3 (each shows the highest version of that part and how many clients run it), Behind latest (behind on front-end, API V2 or API V3), Couldn't read, and Specific version… to list the clients on one version. The sidebar number counts clients behind on any of the three.
  • When a version changes, the row shows the previous version and when it changed. Click anywhere on a client's row to open its details (where the version was found, API answers, version history).
  • If a site's version can't be read, enter it by hand in Edit; it is marked manual.

Create & documentation

New Issue

Create a Redmine issue from the app without opening PJM first.

  1. Choose Project, then Tracker, Priority, and Category (options load from Redmine).
  2. Type the subject, fill the description (you can generate it), then submit.

The issue is created on the selected project using the configured Redmine API key.

The Issue details box holds the fields filled on most issues: Status and Priority (required, default New / Normal), Assignee (developers listed first), Category, Project Name (required) and Client Name. Other Redmine fields are under More Redmine fields. Paste a screenshot with Ctrl+V inside the Description (or use the Screenshot button) to put it right where the cursor is, e.g. under step 1; check it in the Preview tab. Files that shouldn't appear in the text go under Attachments. Max 3 MB per file; large images are shrunk automatically.

The description is written in Markdown, like the Knowledge Base. If your Redmine uses Textile, choose it under Redmine format (it's detected automatically) and the text and images are converted when the issue is sent.

Generate description fills in the layout your team already uses in Redmine for the chosen tracker (section headings learned from recent issues); when there isn't one yet it uses a standard layout. It takes the problem, steps, expected/actual result and notes from Notes for description generator, adds Client, Project Name, category and project from the form, keeps screenshots under the step they belong to, and asks before replacing text you typed yourself.

The default QA format layout produces Environment (App, Module, Menu, Environment, Browser, OS, Version, Client, Project), Precondition, Steps to Reproduce (starting with "Login ke ERP."), Actual Result, Expected Result, Severity / Priority (from the Priority field, or Severity:/Priority: in the notes), Notes and Attachment, and prefixes the subject like [Bug] …. Choose Team layout to use the headings learned from Redmine instead.

Paste from ChatGPT: ask ChatGPT for the bug report in the QA format, click the button and paste the answer (it's picked up from the clipboard when the browser allows). Title becomes the Subject, [Bug] picks the Tracker, Severity / Priority sets Priority (Critical/P0 → Immediate, High/P1 → High, Medium/P2 → Normal, Low → Low), Client / Project in Environment fill Client Name / Project Name, and every other section goes into the Description. Screenshots you already pasted stay under their step.

Knowledge Base

Where the team writes how-to guides for Zahir ERP, ERP One, and MRP so support answers clients with the same steps. Guides are stored in the workspace and visible to every member.

  1. Click Write guide, choose the product, then the Module and optional Submenu from the lists (e.g. Master Data › Contacts). These lists come from Edit menus. For a guide that only applies to one client, also fill in Client; leave it empty for general guides.
  2. Write steps in markdown; paste screenshots with Ctrl+V.
  3. Check Preview, then Save guide (or Ctrl+S).
Screenshots are stored on Cloudinary; guides keep only their links, so the database and backups stay small. Export JSON in Settings backs up guides and menus (with those links).

A guide with a client shows the client name in the list and at the top of the guide. Click the name to open that client's Redmine issues in By Client. Searching for a client name finds their guides.

In the library on the left, open a module to see its submenus; guides without a submenu are listed under General. Inside a module, guides are grouped by submenu.

Edit menus (below the library) is where the team defines each product's modules and submenus and their order. Renaming a module or submenu updates every guide that uses it; items that guides still use can't be removed. The first time, the list is pre-filled from the modules your guides already use.

Other

Telegram & notifications

  • Set Chat ID for the target group or channel, then click Save.
  • Enable Auto-notify so Telegram is alerted for new Ready for Testing issues; test with Send test RFT.

The bell icon shows recent alerts and can enable browser notifications while the app tab is open.

Search & Notes

The magnifier icon (or /) opens global search across plans, issues, clients, and notes. Click a result to jump there.

Notes are quick personal reminders stored in the browser on this device (not cloud-synced).

Shortcuts are inactive while the cursor is in an input field.

Backup & restore

  • Export JSON saves a full backup: plans, summaries, Knowledge Base (guides, screenshots, menus) and your private issue notes. Import JSON restores it.
  • Import JSON restores data from that backup file.
If you are on a team workspace, Delete All Data also deletes teammates’ data. Export JSON first before deleting.

Troubleshooting

Redmine / Telegram unavailable
These features need Google sign-in. Open Settings → Sign in with Google.
Email not allowed
Your Google email is not on the server allow-list. Ask the app owner to add it, then reload.
Telegram not sending
The Chat ID in Settings must match what is registered on the server.
Data differs between devices
Use the same Google account and the same workspace (Settings → Team Workspace).
List shows fewer issues than the sidebar
The sidebar counts every issue in that status. A filter (search, project, priority, date, or a quick chip such as Immediate) can hide some; a yellow note above the list then says "Showing X of Y" with Clear filters. Lists refresh from Redmine when older than 2 minutes and every 5 minutes in the background; the last update time is shown next to the status. Click Refresh for the latest right away.
RFT alerts while tab is closed
Server cron runs about once per day on the Hobby plan. Keep the app tab open for faster browser checks, or rely on Telegram.
